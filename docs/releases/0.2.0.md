# M87 AI Gateway 0.2.0

*Released 2026-11-05*

Run it for a team, and keep answering when a model fails.

### What's new

- **Single sign-on.** People sign in to the console through your identity provider, as an admin or read-only.
  Read-only people can see everything, including captured content when capture is on, but cannot change
  anything. The admin key keeps working for recovery. Off until configured. See
  [single sign-on](https://github.com/m87techlabs/m87-ai-gateway/blob/v0.2.0/docs/runbooks/single-sign-on.md).
- **An audit log that names people.** Each change, sign-in and refused sign-in records who did it, with a stable
  identifier from the identity provider. Actions taken with the admin key say `admin-key`.
- **Fallback routes.** When a model times out, is overloaded or returns a server error, the gateway can try up to
  three other models in order. An application only falls back to models it is allowed to call, and the response
  names the model that answered. Off by default. See [fallback routes](https://github.com/m87techlabs/m87-ai-gateway/blob/v0.2.0/docs/runbooks/fallback-routes.md).
- **A Features page organised by job.** One card each for Authentication, Routing, Caching, Rate limiting,
  Reliability, Guardrails, Logging, Monitoring and Cost tracking, with its state and live numbers. Each opens its
  own page of settings, and shows what is planned. See [what the gateway does](https://github.com/m87techlabs/m87-ai-gateway/blob/v0.2.0/docs/features.md).
- **Alerts that reach someone.** The monitoring profile adds Alertmanager, connected to Prometheus and Grafana. It
  sends nothing until you add a destination, and the guide shows how to add one and prove delivery.
- **Your own Grafana.** Guidance for using an existing Prometheus, Grafana and Loki, and an explanation of
  [how data reaches Grafana](https://github.com/m87techlabs/m87-ai-gateway/blob/v0.2.0/docs/grafana-data-flow.md).

### Changed

- **The store moves to schema 13.** Your applications, keys, logs, usage and settings are kept, but 0.1.2 cannot
  open a migrated store. Back up first; see Upgrade.
- **Everyone signs in again** once, because console sessions use a new format.
- The **Features** item moved to the top of the sidebar.
- `GET /admin/api/features` now returns `capabilities` beside `items`, and each item's `group` is a capability ID
  such as `caching`. `GET /admin/api/session` also returns the role and who is signed in.
- Loki in the monitoring profile now deletes data after 30 days.
- Session cookies are `Secure` behind a TLS proxy when `GATEWAY_PUBLIC_URL` is an HTTPS address.

### Fixed

- Backup failed with a vague storage error when the admin key came from `GATEWAY_ADMIN_API_KEY`.
- Bundled dashboards named the monitoring profile's data sources, so they did not work in another Grafana.
- Two dashboard panels showed a meaningless axis when every value was zero.

### Upgrade

Back up first, because the upgrade cannot be undone in place. From the folder with your `docker-compose.yml`:

```bash
read -rs -p 'Backup password: ' GATEWAY_BACKUP_PASSWORD; echo; export GATEWAY_BACKUP_PASSWORD
docker compose stop
docker compose run --rm -e GATEWAY_BACKUP_PASSWORD m87-ai-gateway --data-dir /data/gateway --backup /data/before-0.2.0.m87backup
docker compose run --rm -T --entrypoint cat m87-ai-gateway /data/before-0.2.0.m87backup > before-0.2.0.m87backup
unset GATEWAY_BACKUP_PASSWORD
```

Then download this version's Compose file and update:

```bash
curl -fsSLO https://github.com/m87techlabs/m87-ai-gateway/releases/download/v0.2.0/docker-compose.yml
docker compose pull
docker compose up -d
```

From a checkout, run `git pull` and `docker compose up -d --build`.

If you set `GATEWAY_ADMIN_API_KEY` yourself, 0.1.2 cannot back up; see Fixed. Back up with 0.2.0 from then on.

To roll back, restore your backup into a new Compose project with the 0.1.2 image, as described in
[run with Docker](https://github.com/m87techlabs/m87-ai-gateway/blob/v0.2.0/docs/runbooks/container-deployment.md). Do not start 0.1.2 on the migrated store; it refuses to
start.

### Known limitations

- Early software: the API and configuration can change before 1.0.
- Single sign-on has been tested with Keycloak only. A removed person keeps access until their session ends, 60
  minutes by default. Admin key attempts are not throttled.
- Fallback routes wait for the first model's error. A server that accepts connections but never answers holds a
  request for the provider's full timeout before falling back.
- **Not ready for direct internet exposure:** `/metrics` needs no key, and there is no built-in TLS. Put a TLS proxy
  with path rules in front. This is the focus of 0.3.
- Verified live against Ollama. OpenAI and other compatible providers are implemented but not yet checked live.
- One instance per data volume. Limits and the cache are per process.

See [what has been verified](https://github.com/m87techlabs/m87-ai-gateway/blob/v0.2.0/docs/validation.md).
